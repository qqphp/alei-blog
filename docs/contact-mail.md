# 关于页留言与邮箱设置

关于资料里的关注文案、交流群名称、说明和二维码可以编辑。二维码未配置时显示待补充。留言与验证码记录在关于菜单下仅供查看，私有数据不经过公开内容接口。

## 初始化

先备份数据库与素材，运行 `npm run db:migrate`，然后在网站设置的邮箱设置中填写服务器、发信邮箱和收信邮箱。无需配置 `MAIL_ENCRYPTION_KEY`：首次保存邮箱设置、加密或解密授权码、计算验证码摘要时，程序自动生成随机 32 字节密钥并保存到私有表 `contact_mail_keys`。读取设置摘要和浏览普通页面不会初始化密钥。数据库事务和锁保证并发首次使用只生成一份；后续运行及重启始终使用数据库中的密钥。

从旧版本升级时，在迁移完成前保留原 `MAIL_ENCRYPTION_KEY`。数据库尚无密钥时，程序将原密钥迁入数据库，并校验已有授权码能够解密；迁移成功后可以移除环境配置中的该项。数据库已有密钥后不再使用旧环境变量。发现旧加密授权码或仍有效的验证码而缺少旧密钥时，停止初始化并提示恢复旧密钥，不生成替代密钥。

邮箱授权码可直接原样填入本地 `.env` 的 `SMTP_AUTH_CODE`，修改后重启 Node 服务。环境授权码优先于后台保存的授权码；未配置环境授权码时，使用数据库中加密保存的授权码。后台读取接口只返回已配置状态，不回显任一来源的授权码；留空保存保留数据库中的原授权码。

默认 SMTP 为 smtp.163.com:465，IMAP 为 imap.163.com:993，均使用 TLS。SMTP 发送验证码和留言通知。连接检查验证 SMTP、IMAP 认证，发送测试邮件后仍需在收信邮箱确认送达。IMAP 不发送邮件，也不同步收件箱。

数据库备份同时包含邮箱密钥、加密授权码和私有记录，恢复完整数据库后无需额外密钥文件。密钥不通过后台或公开接口返回，也不写入日志；取得完整数据库或备份的人也能够解密其中的授权码。不要单独删除密钥记录。

## 运行

`instrumentation.ts` 启动通知任务，每 5 秒检查数据库队列。数据库租约防止多进程同时处理；启动后恢复过期租约。留言保存即计入每日额度，通知首次失败后按 1、5、15、60 分钟重试，最多尝试 5 次。重试沿用同一 Message-ID；SMTP 与数据库之间无法保证投递恰好一次，进程在邮件送达与状态保存之间中断时可能重复投递。

验证码有效期 180 秒，只能消费一次；新验证码发送成功后使旧验证码失效，最多输错 5 次。邮箱统一小写并去除首尾空格。发送尝试限额为同邮箱 60 秒间隔、每天 10 次，同 IP 每小时 20 次、每天 100 次，全站每天 500 次；发送失败仍计次。提交接口每 IP 每分钟最多 20 次。留言每邮箱每天最多接受 3 条，按亚洲上海自然日计算。

公开接口要求同源 JSON 请求、最多 16000 字节正文和空蜜罐字段。仅当反向代理覆盖 X-Real-IP 且 Node 端口不向外开放时，设置 `CONTACT_TRUST_PROXY=1`。默认直连使用共享限流桶，不读取用户提供的 X-Forwarded-For。部署示例已包含 X-Real-IP 覆盖。

留言长期保留，验证码和发送记录 30 天后清理，限流记录过期清理。`CONTACT_MAIL_WORKER_ENABLED=0` 仅用于隔离测试，会停止通知和清理任务。

## 验证

- `npm run test:contact`：隔离数据库，模拟发送；覆盖一次性消费、过期、重发、错误次数、邮箱绑定、限流、跨日额度、并发、任务租约与重试、后台权限和密钥保护。
- `npm run test:contact-ui`：关于页、二维码上传、表单状态、只读后台记录和邮箱设置。
- `npm run test:cms` 与 `npm run test:admin-granular-ui`：现有内容管理回归。
- `npm run test:contact-live`：使用已保存配置，经 HTTP 发送验证码和留言，IMAP 只回读匹配测试 Message-ID 的两封邮件。测试会产生真实邮件与一条私密测试留言，不输出授权码或验证码。

真实验收只读取指定邮件，使用只读邮箱锁，不设置已读标记，也不抓取其他邮件内容。
